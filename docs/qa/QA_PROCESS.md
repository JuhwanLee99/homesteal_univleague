# QA Process (Record System)

## 목적
기록 시스템 QA를 반복 가능한 방식으로 수행하고, 점검 회차별 결과를 독립 보고서로 남긴다.

## 도메인 규칙 (중요)
- Homsteal 경기 구분은 `LEAGUE/PLAYOFF`를 기준으로 점검한다.
- `EUTTEUM/BEOGEUM`은 AUBL 레거시 호환값으로만 취급한다.
- AUBL 반영 시 매핑 기준은 [`docs/homsteal-aubl-division-mapping.md`](../homsteal-aubl-division-mapping.md)를 따른다.

## 저장 규칙
- 모든 QA 결과는 `docs/qa/reports/` 아래에 **회차별 단일 파일**로 저장한다.
- 파일명 규칙: `YYYY-MM-DD-<area>-qa-rNN.md`
- 예시: `2026-03-15-scorekeeper-qa-r01.md`

## 실행 절차
1. 점검 범위 정의
- 예: `기록원(Scorekeeper)`, `스코어보드`, `저장/동기화`, `통계 집계`

2. 사전 확인
- 빌드/린트 수행
- 현재 브랜치/변경 파일 상태 확인

3. 시나리오 점검
- 기능 시나리오별 `통과/실패/주의` 판정
- 실패/주의는 재현 조건과 영향도를 명시

4. 패치 및 재검증
- 결함 수정 후 동일 시나리오 재실행
- `build/lint` 재검증

5. 보고서 작성/저장
- 아래 템플릿 기준으로 회차 보고서 작성
- 다음 회차와 독립적으로 조회 가능해야 함

## 필수 시나리오 (기록원 기준)
1. Undo/Redo 및 redo stack 초기화
2. 일정관리 -> 경기 클릭 이동
3. 포지션 숫자 입력 통일(1~9,0)
4. 실책(reach_error) 타구 방향 이벤트/CSV 반영
5. 주자 수비방해/주루 방해 분리 기록
6. 모달 가시성/스크롤(작은 화면/맥 포함)
7. WP/PB/포일 카운트 반영 및 경계값(3볼/2스트) 처리
8. 저장 실패 시 재시도 및 누락 여부

## 산출물 규칙
- 각 보고서에 반드시 포함
  - 점검 일시(KST)
  - 범위/환경
  - 시나리오별 결과표
  - 발견 이슈 및 조치
  - 최종 빌드/린트 결과
